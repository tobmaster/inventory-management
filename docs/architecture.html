Architecture overview

Factory Inventory Management System

A two-tier demo app. A Vue 3 single-page app talks to a stateless FastAPI service over REST. The service loads JSON files into memory at startup and filters them for each request. There is no database and no authentication.

Data flow

What happens when a user changes a filter, for example Warehouse = Tokyo on the Dashboard.

Request lifecycle

  1. Filter state changesFilterBar writes to module-level refs in useFilters.js, so every view sees the same values.
  2. View re-fetchesA watch() on those refs calls the API. The Dashboard sends 4 requests in parallel with Promise.all.
  3. Query string builtapi.js drops any filter set to "all"; the period filter becomes month (for example 2025-03 or Q1-2025).
  4. Server filters in memoryapply_filters matches warehouse exactly and category/status case-insensitively; filter_by_month substring-matches order_date.
  5. Validated responseThe response_model trims each record to its Pydantic schema before it is serialised.
  6. Reactive renderRaw lists go into refs; computed properties derive totals, charts and tables.

Observations

Things worth knowing before you change the code.

Design choices

  • Stateless reads. Every request re-filters lists in memory. That is fine at this size (about 350 records) and easy to reason about.
  • Global filter store without Pinia. Refs declared at module level in a composable act as a lightweight shared store.
  • Mocked identity. useAuth returns a fixed user with locale-aware tasks; logout only shows an alert.
  • Hard-coded base URL. http://localhost:8001/api appears in api.js and again in Reports.vue; there is no Vite proxy or environment variable.

Gaps found during investigation

  • /api/tasks and /api/purchase-orders are called by the client but are not defined on the server. The Pydantic models for purchase orders exist, but no route uses them.
  • Backlog.vue exists but has no route in main.js.
  • QUARTER_MAP and the quarterly report hard-code 2025, so data from other years falls through.
  • filter_by_month uses substring matching on order_date, not date parsing.
  • total_backlog_items on the dashboard ignores every filter.
